JDC COUNTINGS Backup

Privacy Policy

Effective: 25 November 2026

This policy describes the planned and authorized use of Google user data by the JDC COUNTINGS Backup utility operated by JDC Onlinecenter. Production Google Drive backups have not yet been activated.

1. Data access and collection

The utility requests the Google Drive drive.file OAuth scope. This permits access to specific files created by or authorized for the app, including their content and metadata (such as file name, identifier, size, and folder location). It does not request unrestricted Drive access, Gmail messages, contacts or calendars. OAuth access and refresh tokens and client credentials are needed to authenticate backup operations. The public information website itself does not request OAuth authorization or collect backup files.

2. Use of data

Google user data is used only to create the designated backup folder, upload encrypted recovery archives, read them back to verify integrity, and support authorized recovery and troubleshooting. Database exports may contain financial records, user account data, access settings and operational history. These exports are separate from Google user data and are intended to be encrypted before any upload.

3. Storage and protection

The intended configuration stores encrypted archives in the owner's private Google Drive account. OAuth credentials are stored in restricted local rclone configuration and the dedicated backup runner's secret storage when activated. The private recovery key is held separately by the owner and must not be uploaded to the runner. Temporary plaintext export files are restricted to the backup runner and removed after the job. Access is limited to authorized operators. No method can guarantee absolute security.

4. Sharing and processing

The utility uses Google Drive for file storage and GitHub Actions for backup execution; rclone provides the Drive client. Data is processed by these services only as necessary to operate the authorized backup. Google user data is not sold, used for advertising, transferred to data brokers, or used to train general-purpose AI models. Human access to Google user data is restricted to authorized, necessary recovery or troubleshooting with the user's permission, security investigations, or legal requirements. Google user data is not otherwise shared except as necessary to provide the authorized function, protect security, or comply with law.

Use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

5. Retention, deletion and revocation

Encrypted backup archives are retained in the designated folder until the owner deletes them or approves a retention policy. No automatic deletion is currently configured. The owner can delete backup files using Google Drive, remove the runner's stored OAuth credentials and revoke access through Google Account connections. Revoking access stops further authorized Google API operations but does not itself delete existing archives. The owner controls backup and recovery retention and can request assistance through the support contact below.

6. Public website and contact

These static pages contain no app analytics, forms or application cookies. GitHub Pages may process technical access logs as part of hosting under its own policies. For questions, correction or deletion requests, contact the developer support email displayed on the OAuth consent screen or the JDC Onlinecenter maintainer. Never send database passwords, recovery keys or OAuth tokens in a support request.

7. Changes

This policy will be updated if the backup utility's data access, purposes, storage or retention change. Any expanded Google OAuth access must be reviewed and authorized before use.
